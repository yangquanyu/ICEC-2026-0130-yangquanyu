# 项目四 用户反馈收集说明（交付项③ · 15 分）

## 大纲要求

> ③ 完整源码与 **8 位真实用户使用反馈**（15 分）

## 收集方式（约 10 分钟）

程序本身面向"不想天天刷官网"的学生，反馈收集就用最轻的方式：**把每日通知日报发给真实用户，收集结构化回复**。

1. 从 `output/` 里挑一份最新的日报（如 `digest-2026-11-22.md`），截图或转发文本；
2. 通过微信/QQ 发给 **8 位**同学/室友（真实用户，不重复），附上下方 3 个问题；
3. 把每人的回复要点填进 `feedback_results.csv`（用户身份脱敏为"同学A/室友B"即可，无需真名）；
4. 聊天记录截图可存入 `feedback/screenshots/`（如有）。

## 随日报附带的 3 个问题（feedback_form.md）

1. 这份日报对你有用吗？哪类通知你最希望它帮你盯？
2. 现有格式（标题+日期+链接）够用吗，还缺什么字段（截止时间/发布单位）？
3. 如果明天开始自动收到它，你会天天看吗？什么情况下你会取消？

## 判定标准（自评用）

- 有效反馈 = 8 位真实用户、每人至少回答 1 个问题；
- 反馈要如实记录，**负面反馈同样有价值**——报告里专门分析"哪类反馈被采纳/为什么没采纳"，这正是面试"工程伦理与用户视角"维度的素材。

## 结果汇总

收集完成后，在 `feedback_results.csv` 下方补一段统计分析（多少人认为有用/最被期待的字段/愿意持续使用的比例），并把结论补进 `../iterations/v1.3.0.md`（如有基于反馈的改动）或分析报告。
